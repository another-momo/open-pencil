# T70 计划 · 画布选区采集——input 按钮 + 选区 chip + 消息尾清单

> 日期：2026-09-01。owner 新任务（当日指令原话）：「在 input 输入框的上方新增一个按钮，其含义是『采集画布选区』，点击后就会将采集到的信息带到输入框中，输入框中出现一个特殊 UI 块（可删除）代表刚刚的画布选区，类似「@画布选区-1」，以便实现这种输入语义：『将「@画布选区-1」变成「@画布选区-2」的风格』，在消息最后追加引用的画布选区的具体信息清单，以便让 agent 知道每个画布选区具体代表画布中的哪个节点。」

## 0. 现状侦察（2026-09-01 实证）

- prompt 面已有「用户选区引用」纪律（longform.md 通用纪律第 4 则，`[画布选区]` 前缀），但**只有纸面协议，没有任何 UI/消息面实现**——用户无法真实产生该引用。本任务把它做实。
- 前端读选区已有先例：`active-design.ts:378 findSelectionImageNodes` 遍历 `store.state.selectedIds`（T66 需求单素材挂选区即走此路）。本任务选区采集是**广义节点**（不限 IMAGE fill），读取面同一（`store.state.selectedIds` + `graph.getNode`）。
- 消息提交链：`ChatInput.vue:68 emit('submit', text)` → 父级 → client → service。清单纯文本拼接进提交 text 即可，不动协议/后端。
- 画布内 agent 侧 `get_selection` 工具（packages/core/src/tools/read/selection.ts）与本任务无关（那是 agent 主动读；本任务是用户主动注入）。

## 1. 产品设计定稿（owner 原话 + 补全裁决）

1. **按钮**：input 输入框上方（ChatInput 工具条区），label「采集画布选区」。点击时取**当前页** `selectedIds`：
   - 空选区 → 不产生 chip，轻提示（复用现有 toast/内联提示件，若无则按钮短暂文案反馈）。
   - 非空 → 在光标处插入一个内联选区 token（见 §1.2——与文字混排的特殊渲染文本块，不设独立 chip 栏）。
2. **选区标记 = 输入文字流内联 token（owner 2026-09-01 二次裁定）**：采集结果**不是独立 chip 栏里的 chip**，而是一个**与文字混排的内联标记**——渲染上是有特殊样式的文本块「@画布选区-N」，语义上占据文本流中的一个原子位置，可随文移动（前后的文字正常环绕编辑）、可整体删除。只有这样才能承载「将「@画布选区-1」变成「@画布选区-2」的风格」这类句内引用语义。N = 本次草稿内采集序号（从 1 递增；**发送后重置**——序号作用域 = 当前草稿，与消息尾清单同生命周期）。多次采集产生多个 token；同一组节点重复采集**不去重**（两次采集可能是用户有意区分时刻/语义，清单如实记录两条）。
   - **插入位置**：点击采集按钮时插入到**当前光标处**（无焦点则追加到文末）。
   - **载体技术选型**（现状 = 纯 `<textarea v-model>`，textarea 无法内嵌渲染标记，两条路线）：
     - **路线 A（推荐）：overlay 高亮 textarea**——保留 textarea 承载输入/IME/光标语义，下层叠一个同步渲染的 backdrop div，把文本流里的 `「@画布选区-N」` 片段渲染为高亮样式块（Twitter mention 高亮同款技法）。token 在文本模型里就是字面占位串；**原子删除**靠 keydown 拦截实现：光标紧邻完整 token 时 Backspace/Delete 删除整段占位串。风险低、改动面小。
     - **路线 B：contenteditable**——token 为 `contenteditable="false"` 的原子 span，天然整体选中/删除、任意混排。代价：IME 合成、粘贴净化（粘贴文本不得复活 token）、光标管理都要自实现，回归风险高。
     - **裁决：路线 A**，理由 = 不改变输入语义面（T27 草稿回填、isStreaming 禁用、Enter 提交/Shift+Enter 换行、copy/cut 拦截全部保留），仅在渲染层与删除键行为上加 token 感知。若实施中发现 overlay 同步（滚动/折行对齐）在本仓样式体系下不可控，升级路线 B 并记录偏差。
3. **token 数据**：文本模型里是字面占位串 `「@画布选区-N」`；旁挂一份草稿期 token 登记表（Map: N → { pageId, nodeIds[], capturedAt 快照（节点名+类型，tooltip 用） }）。发送时以**发送瞬间**的 graph 状态生成清单（节点可能在采集后被改名/删除——清单行标注当前实况，已删节点标「已删除」）。占位串与登记表的一致性纪律：用户手动删掉文本里的占位串 = 该 token 失效（提交时以文本流实扫到的占位串为准生成清单，登记表里未被引用的条目丢弃）；用户手打 `「@画布选区-9」` 无登记表条目 → 清单行标「未采集的引用」（诚实告知 agent，不假装有节点）。
4. **消息尾清单格式**（追加在用户文本之后，空行分隔，与 longform `[画布选区]` 纪律同前缀）：

   ```
   [画布选区]
   @画布选区-1 = 节点 1:23「主标题」(TEXT)
   @画布选区-2 = 节点 4:56「主视觉」(FRAME) + 节点 4:57「装饰」(VECTOR)
   ```

   - 一个 token 可含多节点，清单一行内 `+` 连接；节点显示 id + 名称 + 类型。
   - 该清单只进当次提交文本（agent 可见），**聊天气泡显示拼接后全文**（首版不做气泡特判渲染——token 在气泡里即字面「@画布选区-N」，与输入期渲染有落差，接受并记录；若 owner 验收时要求气泡也高亮，转后续小任务）。

5. **草稿回填**（T27 失败回填纪律）：提交失败回填时文本（含占位串）与 token 登记表一并恢复；发送成功后两者清空、序号归 1。

## 4. 验收

1. 空选区点击 → 无 token + 提示；有选区点击 → 光标处插入「@画布选区-1」且渲染为高亮块。
2. 混排场景：在 token 前后正常打字、改字，token 随文移动；光标紧邻 token 按 Backspace → 整个 token 一次删除（不留半个占位串）。
3. 两 token 场景提交「将@画布选区-1变成@画布选区-2的风格」→ 后端收到的文本尾部清单两行，id/名称/类型正确。
4. 采集后删除画布节点 → 清单标「已删除」；手打无登记占位串 → 清单标「未采集的引用」。
5. 发送后 token 登记表清空、序号下次从 1 开始；提交失败回填文本 + 登记表恢复。
6. 门禁：相关测试 + lint/typecheck（视触碰面）unpiped 全绿。
