## 端到端真值再生（dev server 起动后）

1. **场景 1（envelope 兼容路径）**：用户消息首行 `[新建意图确认 modeId=longform profileId=p1]` → `stripNewIntentEnvelope` 命中 → `intentConfirmed = true` → `setupDesign` 通过 args 一次性确认 → 建框成功（pluginData 未写，与原 T61 行为一致）

2. **场景 2（pluginData 路径 + ChatPanel 拦截）**：AI 调 `setup_design({ modeId: 'longform', briefId, profileId: 'p1' })` 但无信封 + pluginData 未确认 → core 返 `awaiting_new_intent_confirmation` 信封 → ChatMessage 检测 status 字段挂 ChatAwaitingIntentCard（替换通用折叠工具卡）→ 用户点 Confirm → POST `/api/pi/intent-confirm` 写 pluginData 三键 → `chat.value?.stop()` 截停 SSE → 系统行注入「已确认新建意图——可以重发需求继续创建」→ 用户重发 prompt → `prepareTurn` 探针读 pluginData confirmed=true → `intentConfirmed = true` → AI 重放 setup_design → core `readNewIntent` 命中 → 落图成功 → `clearNewIntent` 清三键 → 设计正常出现在画布

3. **场景 3（用户取消）**：步骤 2 中用户点 Cancel → `chat.stop()` + 系统行「已取消新建意图」→ 用户改 prompt 重发即可（pluginData 未写，下次 prepareTurn 按空 state 走）

4. **场景 4（多实例隔离）**：dev server 重启后 pluginData 三键仍存在（document root sharedPluginData 持久化）→ 用户重发需求命中 → 落图成功 → 清三键（防止下次误用旧 modeId）

5. **场景 5（pluginData 真值持久）**：保存 .fig → 重新 import → pluginData 三键仍存在（T91a 钉 round-trip 5/5）→ 走场景 2 完整流程
