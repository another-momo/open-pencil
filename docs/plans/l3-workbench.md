# Layer 3 营销工作台交互改造：产品构想与规划

> 本文档沉淀 Layer 3（工作台交互改造）的产品构想与设计。**状态与任务进度见 `README.md`（唯一状态来源）**。
> 上层总览见 `00-overview.md`，L2 设计见 `l2-agent-mode.md`。
>
> 结构：§1 问题定位 → §2 概念模型 → §3 交互方案（按三类信息 + 横向工作流）→ §4 模块路线图 → §5 待决事项。

## 1. 问题定位

### 1.1 L3 的本质

L2 三轮冒烟测试证明对话驱动的工作流可行，但暴露同一模式：**高频、结构化的交互在纯对话里效率低**（选方向要打字、checkpoint 选项要复述、素材类型靠推断、品牌资产每次重新解释、生图 60-70 秒无反馈）。

**L3 不是替代对话，而是把结构化交互从对话里解放出来。**

### 1.2 三个断点

更深层的判断：对工作影响最大的不是交互摩擦，而是**流程形态与工作形态的不匹配**——

```
当前流程 = 一次性、直线、从零开始、到画布为止
真实工作 = 反复出图、系列迭代、同一品牌、以发布为终点
```

| 断点 | 表现 | 对应方案 |
|---|---|---|
| **起点断点** | 每次开始都是空白对话：品牌/类型/内容全部重新提供。真实运营 80% 的图是"同一品牌的下一张"，成本乘以每次使用 | 品牌包（§3.3）+ 类型显性化（§3.1）+ 需求单（§3.2） |
| **迭代断点** | 真实工作是"先来一版 → 换风格再来 → 同系列做 5 张"，当前单线流程不支持系列化/变体 | 制作清单 + 派生（§3.4） |
| **终点断点** | Phase 4 结束 = 对话结束，但工作的终点是"图发布出去"，中间隔着导出 | 导出流程（§4） |

## 2. 概念模型

### 2.1 三类信息模型

设计开始前用户需提供的信息分三类，**基本独立、偶有交叉冲突**：

| 信息类 | 性质 | 确认时机 | 代码强制（确定性可判定） | prompt 引导（需要判断/生成） |
|---|---|---|---|---|
| **宣传内容** | 每张图都变 | 每次设计，CP1 校准 | ——几乎没有 | 全部：问答/需求单 → 设计状态 → 写作约束（禁虚构、`¥__` 占位） |
| **素材类型** | 每张图选择 | 每次设计，推断为主、选择器兜底 | 尺寸、锚点物化、结构约束（setup 执行 + validate 校验） | sectionPlan、styleGuide、custom（工具结果注入） |
| **品牌规范** | 跨设计不变 | **一次配置、永久生效** | readonly 锚点（logo/品牌名，注册表 + validate） | 品牌色/字体/语气/禁用元素（注入上下文，AI 应用时遵守） |

核心原则：

- **可判定性划分**：能写成"对比当前值和应有值"的检查进代码，其余进 prompt（L2 已验证的方法论）
- **起点交互的终态**：用户日常只需面对**宣传内容**一个必答项；素材类型多数被推断掉；品牌规范静默生效
- **冲突处理**：检测进代码（validate 扩展），声明进 prompt（AI 必须显式告知适配行为，如"已把品牌细体替换为粗体以保证可读性"，不得静默牺牲品牌规范）

### 2.2 要素归属与冲突仲裁

**从属于素材类型（类型层）**：尺寸/比例、section 结构/密度、锚点配置、平台规范（审核/安全区/平台调性）、字号尺度、CTA 形式。

**跨素材类型（品牌层）**：品牌名/logo、品牌色（需分层：主色/辅色/功能色）、字体（字族跨类型，字重字号按类型适配）、语气/受众、禁用元素、活动信息（**内容跨类型、表达按类型裁剪**）、产品图库。

**冲突点（品牌层 × 类型层）**：

1. 品牌色 vs 可读性（浅色主色在小尺寸 CTA 上对比不足 → 色板分层）
2. 品牌字体 vs 尺寸约束（细体在小 banner 不可读 → 类型层可强制字重/替换展示字体）
3. logo 位置 vs 锚点模板（VI 规范 vs 类型默认排布）
4. 活动信息密度（同档活动，DSP 只放"5折"，详情页放完整价格表）
5. 锁定风格 vs 平台调性（品牌"高端极简" vs 小红书"热闹种草风"）

**仲裁规则（共识）**：

- 硬约束永远赢：禁用元素/合规，无条件覆盖一切
- 软偏好类型层可适配，但必须显式声明
- logo 位置等 VI 硬规范：作为品牌包可选字段，声明后覆盖类型锚点模板
- 待决：品牌规范 vs 平台适配的默认优先级是否做成"品牌约束强度"字段（§5）

### 2.3 概念分层

```
品牌包（跨设计不变）
  → 宣传活动 campaign / 制作清单（跨类型、同档期不变）
    → 素材类型（规格层：尺寸 + 平台规范，小而稳定）
      → 素材模板（方案层：结构排布 + 锚点 + 默认骨架，多而增长）
        → 单次设计（最终产物）
```

**类型 vs 模板**：

| | 素材类型（type） | 素材模板（template） |
|---|---|---|
| 本质 | 规格层：尺寸、平台规范 | 方案层：结构排布、锚点、默认骨架 |
| 回答的问题 | "它是什么" | "它长什么样" |
| 关系 | 1 | : N |
| 变化频率 | 小而稳定（7~15 个预设） | 多而增长（默认模板 + 用户存模板积累） |

- **判定标准**：两个设计若能承载同样内容、投放到同一平台广告位，就是同一类型；差异在排布方案即模板。例：朋友圈广告品牌区在上 vs 在下 = 同一类型的两套模板
- **当前实现的概念混淆**：类型注册表把锚点写死在类型上，实际是"7 个类型各绑死 1 套默认模板"。现有实现兼容（默认模板 = 当前类型配置），引入多模板时再解耦
- **validate 精确化方向**：结构校验对象是当前生效的**模板**，不是类型本身
- **模板积累策略**：不自建库（内容生产成本高、约束 AI 灵活性），留"把当前设计存为模板"入口自然积累；方向提案现场生成是模板少时的回退路径

## 3. 交互方案

### 3.1 素材类型：推断为主 + 显性化

**结论**：自然语言 + AI 推断作为主路径合理（平台命名类请求几乎直查，"一句话开始"是起点摩擦极限），但需补三个推断机制原理性覆盖不了的缺口：

| 缺口 | 说明 | 方案 |
|---|---|---|
| **变体类型** | 类型词不含尺寸信息（DSP 的 IAB 尺寸、海报 A3/A4/自定义） | **必须问**（按类型的硬规则，非"不确定才问"——模型天生过度自信）；或默认最常见 + 声明 + 易切换（待决） |
| **泛化词汇** | 同词不同物（"海报"朋友圈 vs 印刷、"封面"公众号 vs 视频号） | 同上，AI 主动给选项 |
| **可发现性** | 注册表不可见：不知道支持哪些类型、新用户无引导、注册表外类型无逃生舱 | 轻量类型入口（chips / 空状态画廊）+ 自定义尺寸兜底类型 |

**立场（讨论中修正）**：反对的是**阻断式前置**（不点选不让输入），不是类型显性化。目标用户（运营）被 Canva/稿定训练的心智模型是"先选规格再做图"，且推断错误成本（整轮作废）远高于确认成本（点一下）；但用户表达意图的权利不应被门槛挡住。

**推荐形态：推断负责猜，选择器负责让猜测可见可改**——

- 输入区上方类型 chips，**本地预推断**（chips 监听输入文本做关键词直查，注册表 label 即关键词）在输入过程中即时高亮选中态，用户可直接改；AI 执行时以 chip 状态为准
- **类型解析优先级：用户显式选择（chip）> 需求单声明 > AI 推断**——用户点过的 chip 是硬约束，AI 不得覆盖
- 发送消息 = 隐式确认（待决：推断未确认时发送键是否提示）
- 空状态时为模板画廊，天然完成新手引导与可发现性
- **声明习惯**：setup 后 AI 必须一句话报出"已按 X 类型 1080×1080 创建"，推断错误第一时间可拦（switch 模式已支持）

### 3.2 宣传内容：需求单节点

核心目标：**高效收集宣传内容**。关键洞察：内容混着两类信息——意图型（风格/调性，适合选项识别，方向提案已高效）；事实型（品牌名/价格/日期，短答案）才是收集效率的问题所在。

#### 3.2.1 通道分工

```
意图走对话（做什么、什么风格、什么活动）
素材走画布（图片、参考、已有设计、需求单）
```

- 画布做输入比聊天附件更原生（附件暂缓，仅剩"即抛型快速引用"的小价值）
- 输入/产出边界约定：**setup 创建的设计根 frame = 产出；根 frame 之外的游离节点 = 潜在输入**
- **技术短板**：AI 看不懂画布图片内容（无视觉通道），素材角色区分必须靠用户声明/命名

#### 3.2.2 需求单节点（核心载体）

用一种**特殊标记的 FRAME**（约定命名/pluginData + 便签式视觉样式；**不做新节点类型**——.fig 格式兼容性是硬约束）作为人和 AI 均可读可写的专用沟通载体。

**核心属性**：

- **自包含输入包**：活动信息、文案、素材图、备注收在一个节点子树，AI 读输入 = 读这一个节点
- **双向读写分区**：用户编辑区（内容区/素材区）+ AI 结论区（**只追加不改写**）；AI 结论区**只落已确认的结论**（锁定的方向、最终活动信息、素材映射）——**回显提问走 chat（checkpoint 语义），确认后的结论才落 AI 结论区**，需求单保持"档案"而非"对话"
- **持久化**：对话是过程，需求单是档案——重开文档 brief 仍在，顺带缓解"继续未完成设计"的上下文问题
- **复用即复制**：系列第二张 = 复制需求单改改；一份需求单可驱动制作清单里的多个类型（campaign 的实体载体）

**内部结构（已实现，视觉设计经 UI 设计模式打样后定稿）**：

```
需求单（标记 FRAME，560 宽，琥珀便签底 #FEF6D6 + 投影，横向两栏）
├─ 左栏（需求内容，纵向）
│   ├─ 标题区：AccentBar + "需求单" + 副标题"填好后对 AI 说：按需求单做一张朋友圈广告"
│   ├─ 内容区（白卡片）：示例文案（用户照着改）+ 字段清单提示
│   └─ 素材区（白卡片）：素材槽位网格 = 1 个示例条目（素材条目：图片位在上、用途备注在下）
│      + 3 个"添加位"（加号占位，非条目）+ 备注说明
└─ 右栏 AI结论区（深一档琥珀卡片 #FCD34D，172 宽撑满高度）
    ├─ 标签 + 说明 + 结论列表（AI 追加处）
    └─ 空状态"（尚无结论）"（首次追加后自动隐藏）
```

**素材条目结构**：纵向槽位（图片位在上、用途备注 caption 在下），frame 名为 `素材条目`；`添加位` 只是引导占位，AI 不读。备注三语义不变：指定用途 / 仅作参考 / 未标注（AI 自行安排并在 chat 回显打算）。

**实现备注**：①不做新节点类型，pluginData 标记（`open-pencil-marketing: role=brief`）防改名失效；②lucide 图标需异步获取，代码版加号用矩形绘制；③TEXT 换行文本的宽度填充用 `layoutAlignSelf: 'STRETCH'`（`counterAxisSizing: 'FILL'` 对 TEXT 不生效，仅对 FRAME 生效）——命令式创建节点时的隐藏机制，layout 防回归测试已覆盖；④微文案面向用户操作引导（"双击替换示例""直接拖入图片"），不写 AI 规则。

**创建入口（V1）**：chat 输入区"新建需求单"按钮，生成带三区结构的标记 frame；AI 在 Phase 0 检测到无需求单时**不自动创建**（避免每次设计都生成空单），仅在用户要求或素材复杂到需要时建议创建。

**保真的边界**：需求单文本默认原样使用；文案过长排不下等情况需要删改/精简时，**必须经用户确认**，AI 不得擅自改写。

#### 需求单的生命周期

定位：**准备充分用户的可选工具**，非每次设计必需（随手型用户走纯对话即可），因此不自动创建。

**① 创建（三个入口）**

| 入口 | 场景 |
|---|---|
| chat 输入区"新建需求单"按钮（主入口） | 用户主动点击 → 在当前视口位置生成需求单 |
| AI 建议制 | AI 检测到复杂需求（内容/素材较多）时建议"要不要先建需求单？"，用户同意才创建 |
| AI 归一化 | 用户已把零散文本/图片堆在画布上 → "整理成需求单" → AI 把游离节点收编进新建的需求单 |

**② 初始形态**：便签样式标记 frame（结构见 §3.2.2 内部结构）——标题 + 副标题操作引导、内容区示例文案、素材区 1 个示例槽位 + 3 个"添加位"、AI 结论区"（尚无结论）"空状态。所有提示文案面向用户操作（"双击替换示例""直接拖入图片"），结构约定做成可见示范，无需读文档。

**③ 填写（全部画布原生操作，零新 UI）**：双击文本直接编辑；拖图进素材区；复制示例条目增加素材；也可拖新图后让 AI"帮我把素材区的图整理成条目"。

**④ 使用**：chat 一句"按需求单做朋友圈广告"（或仅"做个朋友圈广告"）→ AI Phase 0 按 pluginData 标记找到需求单 → 读取 → chat 回显理解 → CP1。聊天消息始终只要一句话，需求单承载所有重内容。

**⑤ 过程与复用**：确认的结论由 AI 追加到 AI 区；同活动下一张 = 复制需求单改改再用（驱动制作清单的 campaign 载体）。

#### 3.2.3 素材指代的粒度阶梯

| 粒度 | 机制 | 场景 |
|---|---|---|
| 单张指代 | **选区**（选中即输入） | "用这张图做 banner"、"基于选中的设计派生" |
| 批量映射 | **命名 + 回显**（文件名/图层名 = 映射元数据，AI 报映射表确认） | 详情页 10 张产品图对 10 个卡片 |
| 角色区分 | **声明**（备注/自然语言） | "这是产品图"、"仅作风格参考" |

**三条路径的优先级**：需求单素材区（组织化，多素材）> 选区（单点指代）> 游离命名图（快速即抛）。AI 读输入先找需求单，没有再退后两者。

#### 3.2.4 收集流程：分层 + CP1 自适应

1. **请求本身**（类型+主题）——一句话，已有
2. **CP1 合并问询**——方向选项与事实问题合并一条消息，给"直接出草稿（占位符兜底）"的显式出口；**CP1 形态随输入完整度自适应**：输入稀疏→提问，输入丰富→回显+确认，输入完整→只剩方向选择。保真文案在回显中标注"将原样使用"
3. **占位补全清单**——出稿后未填的具体信息（`¥__` 等）以可点击清单呈现，点击定位节点，用户画布直改（画布本身就是最好的表单）
4. **复用**——需求单复制（见 §3.2.2）；活动信息跨对话复用方式待决（§5）

**AI 角色修正**：需求单写入真实文案后，AI 从"文案+设计"（编造内容，专业用户大忌）回归"纯设计排版"；画布文本 = 保真天然成立（写在单子上的字语义就是"用这些字"）。

### 3.3 品牌规范：品牌包（⏸ 暂缓，优先级最低）

范围已明确（跨设计不变集合）：品牌名/logo/品牌色（分层：主色/辅色/功能色）/字体/语气/禁用元素/产品图库。交互形态与字段设计构想未定型，**暂缓推进，待想清楚后再议**（待决项保留在 §5 备查）。当前阶段品牌信息的临时承载方式：需求单用户区手写 + 每次设计 CP1 询问。

### 3.4 多类型工作流：制作清单

真实工作常态：一档活动铺多渠道（朋友圈 + 小红书 + DSP + 公众号封面）。

**原则：表达不阻塞、执行串行、状态可见。**

- 用户可一次性表达完整诉求（自然语言"做周三5折的朋友圈+小红书+DSP"，或 UI 多选类型），系统落成**制作清单（production queue）**
- **共享决策只做一次**：方向、活动内容、品牌信息在清单级确认（CP1 对整个清单生效）
- **逐类型执行**：每个类型走自己的骨架 → 内容 → 校验
- **状态机**：`待制作 / 制作中 / 待确认 / 已完成`，可增删、调序、插队
- **派生融入**：派生路径（"基于这张再做 X 版"）= 往清单追加一项并指定源设计为参考，是主路径

**跨类型复用的价值排序**：图片资产（hero 图 67 秒，复用 hash 换裁剪，省时且保证多渠道一致）> 文案/活动信息 > 风格锁定。**结构不复用**——每种类型骨架重来（setup 切换模式已支持）。

**实现层面推论**：当前营销会话状态按 SceneGraph 键控（一份文档一个类型），制作清单要求一份文档多类型并存，注册表需改为**按根 frame 键控**。
