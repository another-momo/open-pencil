# 坐标系与几何参考帧

在任何需要算「画布中央 / 标题区中心 / 接缝位置 / scaffold 几何」之前读本篇。
正文不重复坐标语义；只在本节触及坐标与几何的精确语义。

## 坐标系总览

| 项         | 值                                                 | 备注                                           |
| ---------- | -------------------------------------------------- | ---------------------------------------------- |
| 原点       | 设计区根框**左上角**                               | 与画布左上角重合；无 page-level Y 轴翻转       |
| X 轴       | 向右递增                                           | 正方向 = 右                                    |
| Y 轴       | **向下递增**                                       | 正方向 = 下；屏幕坐标（CanvasKit / Web 标准）  |
| 单位       | 像素（px）                                         | JSX 里一切 `w/h/x/y` 都是 px，**不是 vw/vh/%** |
| 坐标系层级 | 每个节点的位置 = **相对父节点**（parent-relative） | 不存在全局坐标；层级链由 `parentId` 串成       |

一句话总结：和浏览器的 `<div>` 一致——左上为原点，向右向下为正。

## 误判高发（按事故频度排序）

1. **「画布中央」≠ (-W/2, -H/2)**。画布原点在左上，「中央」是 `(W/2, H/2)`。负值 = 落到画布外。
2. **「标题在画面下方」= y 较大**，不是 y 较小。下方是 Y+ 方向。
3. **「标题偏左」= x 较小**，与 X+ 方向一致。下意识按数学 Y+ 写「向上」会把标题挪到画布顶。
4. **JSX 里 x/y 是父节点内偏移**，不是画布绝对坐标。子节点是父节点的局部 `x/y + 父节点自己的世界位置`，层级链算到底才是画布坐标。
5. **百分比不存在**——没有 `w="50%"`，只有 `w="fill"`（在 flex 父内才有意义）或固定 px。
6. **hug / fill 的子节点仍然有 x/y**，但 hug 父的 x/y 是父起点；fill 子在 hug 父内宽度归零——「fill 在 hug 父里塌陷」是常见坑。

## 几何记录的口径

`prepare_hero_scaffold` 返回的 `scaffold` 记录，下游**只读不散传**——即下游消费方读这个 record，不自己再去翻底层节点的世界矩阵。

| 字段                 | 语义                                                                                                                          | 单位           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `scaffold_id`        | 参考帧节点 id（也是生图落位时的 `replace_id`）                                                                                | 节点 id 字符串 |
| `width` / `height`   | 参考帧画幅（= 图像 API 的 width/height 必传参数）                                                                             | px             |
| `underlap_px`        | hero 图底部与下文的过渡区高度（按 W 缩放）                                                                                    | px             |
| `transition_zone_px` | 实际生效的过渡区高度（`min(underlap_px, transition_zone_px)` 后再 clamp）；profile 标 `clamped: true` 时下游遵守 clamp 后的值 | px             |
| `source_node_id`     | 被克隆为参考帧的标题版式节点（只读，不修改）                                                                                  | 节点 id 字符串 |
| `root_id`            | 设计区根框节点                                                                                                                | 节点 id 字符串 |

## 落位几何（hero 物化后）

阶段 2 选中的候选节点、阶段 3 跑 `compose_backdrop` 之后，几何关系如下：

```
画布根框  (0, 0) ─────────── (W, 0)
        │
        │  根框内 hero 槽
        ▼
hero 节点  (x_hero, y_hero) ── (x_hero + W, y_hero + H_hero)
        │
        │  hero 底部 underlap
        ▼
过渡区    (x_hero, y_hero + H_hero) ─ (x_hero + W, y_hero + H_hero + underlap_px)
        │
        ▼
后续节次  (0, y_hero + H_hero + underlap_px) 起逐节堆叠
```

- H_hero 默认 = W（profile 另有规定按 profile）。
- underlap_px 默认 100 @ W=750，约 140 @ W=1080；按 W 线性缩放。
- 后续节 x 默认 = 0（贴根框左）；非贴根的场景通过 `x={…}` 显式偏。

## 校准自检（`describe` + `calc` 双查）

- `describe` 树摘要行报每个节点的 `(x, y, w, h)`——逐节点对比手算期望值即机检。
- 任何 `x/y` 涉及算术（中央 / 三等分 / 段中线）一律 `calc`，**禁心算**。
- 「标题压在 hero 中央」= `x = calc((W - titleW) / 2), y = calc(heroY + (H_hero - titleH) / 2)`——不写 `x: -50, y: -50`，那是左上偏移。
- `x + w > W` 或 `y + h > H` 时 describe 报 overflows（裁出根框）——是「中央算错」的典型表现，**不是渲染 bug**。

## 反模式（自检清单）

- 负坐标一律视为嫌疑（hero-first 默认不存在负坐标场景；出现先回查语义）。
- x/y 与父级 flex 模式冲突：flex 父内显式 x/y = 绝对定位（出自动布局），与 justify/items 互斥。
- height hug 时不写 `y`——hug 父的位置不写 y，否则上边距会因 h 计算时机错位。
- scaffold 几何记录散传 = 后续节各自重算 = 漂移——一律读 record 字段。
