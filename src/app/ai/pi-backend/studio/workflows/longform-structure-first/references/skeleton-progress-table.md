# 进度判定表（续作现场）

续作（resume）现场 = 三重 ground truth：画布产物（实物）+ brief 结论区（日志）

- 会话历史（未答表单）。本表是「按画布实物判定续作起点」的口径；resume 协议
  正文已点「按落盘 mode 组装本 workflow」+「AI 按下序读现场重建」，本表补
  「画布长什么样 → 该从哪段起」的硬性对照。

## 进度判定（按画布实物）

| 画布实物                       | resume 起点                          | 阶段          |
| ------------------------------ | ------------------------------------ | ------------- |
| 仅 `setup_design` 根框         | 重跑阶段 1                           | 0 末 → 1 起   |
| 根框 + 骨架渲染完成            | 已过 CP2，重跑阶段 2.5 / 阶段 3 起段 | 2 → 2.5 / 3   |
| 根框 + 骨架 + 视觉环境物化完成 | 阶段 3 起段                          | 2.5 末 → 3 起 |
| 根框 + 骨架 + 部分节填充       | 从下一未填节续填                     | 3 中段        |
| 全节填充 + 未 polish           | polish 段                            | 3 末 → polish |
| 全节填充 + polish 已过         | 阶段 4 终审                          | 3 末 → 4      |

## 判定顺序

1. `read_brief` 读内容区 + AI 结论区——拿到「本设计已记录到哪一步」的日志线索。
2. `describe` 根框看子节点——是骨架（多个命名 Frame）还是节（带文字/图）还是根框。
3. `look` 根框验结构与配色（与 CP1/CP2 锁定比对）。
4. 三处冲突时**画布实物为准**——结论区与画布不符时在结论区补一行勘误。

## 各档的「未答表单」处置

- 画布停在 CP1（仅根框、无骨架）→ 会话历史找 CP1 表单是否已回：未回 = 续等，不重发；已回 = 阶段 1 已完成，下一步是阶段 2。
- 画布停在 CP2（骨架完成）→ 找 CP2 表单：未回 = 续等；已回 = 阶段 2 完成，下一步是阶段 2.5。
- 画布停在阶段 2.5 / 阶段 3 中段（部分节）→ 阶段 2.5/3 内不重发 CP，只看节级自检行 + 跨节一致性检查节奏是否到（每 3 节一查）。

## 反模式

- 凭 brief 结论区单源判定进度——画布可能与结论区漂移（节点被删、节未按计划填）。三源必查。
- 续作时不读会话历史重发同一表单——已答 = 续跑，未答 = 续等，不可重发。
- 把「部分节填充」误判为「未开始阶段 3」——节级自检行 + 跨节一致性检查已写就 = 阶段 3 在跑。
- 进度判定只看节点数不看节命名——命名（HeroImg / ProductImg / …）是有/无的关键证据，结构先行的命名是按 CP1 大纲定的。
