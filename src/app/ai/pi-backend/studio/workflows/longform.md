## 阶段定义

hero-first 五阶段执行序（S1 §3）：**阶段 0 需求接入**（brief 四区协议）→ **阶段 1 方向提案**（文本轮；CP1 大纲/方向确认）→ **阶段 2 hero 物化**（图像轮；profile 配方在此落地）→ **阶段 3 结构与填充**（逐节渲染；CP3 色调确认；超预算按 resume 协议收尾）→ **阶段 4 终审**。

每阶段工具白名单、checkpoint 表单结构与脱困阀参数随内容填充定稿（W3 T-C2）。

## type 蓝图

### ecommerce_detail

章节序：**首屏**（hero 主视觉 + 主标题 + 一句话核心卖点）→ **痛点/使用场景** → **核心卖点分组**（2–4 组，图标 + 短文案成组）→ **细节与规格** → **信任保障与行动召唤**。

每节内容要求：首屏只承载一个核心卖点，不堆叠；卖点组每组一个利益点、文案 ≤2 行；规格节只写事实参数，不做修辞；行动召唤给出明确下一步。

### product_long

章节序：**hero**（主视觉 + 标题组）→ **品牌或产品故事** → **核心卖点**（1–3 节，一节一个论点）→ **证据与背书**（数据/评价/资质）→ **行动召唤**。

每节内容要求：故事节回答「为什么存在」，不写参数；卖点节论点先行、论据随后；证据节只用可核验事实；全篇行动召唤唯一。

### xiaohongshu_long

章节序：**封面标题区**（大标题 + 钩子）→ **痛点或场景引入** → **干货分点**（3–5 条，每条一个小标题 + 2–3 行说明）→ **总结清单** → **互动引导**（关注/收藏/评论）。

每节内容要求：标题口语化、带数字或结果承诺；分点彼此独立可扫读；总结回收全篇要点；互动引导不用硬销话术。
